# Nebula: Research Summary Table

**Paper:** [Nebula: Proving Machine Executions via Folding Schemes](https://eprint.iacr.org/2024/1605)

**Authors:** Arasu Arun and Srinath Setty  
**Record:** 2026 IEEE Symposium on Security and Privacy (SP);

**Interpretation note:** This table summarizes the Nebula paper. Statements marked **Author-stated** are presented as claims, definitions, assumptions, constructions, results, or caveats in the paper. Statements marked **Research interpretation** are analytical synthesis or proposed directions and are not attributed to the authors.

| Item | Summary |
|---|---|
| **Research problem** | **Author-stated:** zkVM provers face a space-complexity bottleneck: storing information proportional to the number of program steps makes proofs for long-running computations impractical. Two additional obstacles are efficient sequentially consistent read-write memory and the “pay-per-use” cost of representing many possible machine instructions when most are not executed. [Nebula PDF, pp. 1–2] |
| **Main contribution** | **Author-stated:** Nebula combines three techniques: commitment-carrying IVC for incrementally committing to non-deterministic advice; a read-write memory argument based on multiset hashing; and a universal switchboard circuit that turns off uninvoked instruction circuits. These components are combined into an IVC scheme and a prototype EVM zkVM. [Nebula PDF, pp. 1–2, 7–11] |
| **Commitment-carrying IVC** | **Author-stated:** A CC-IVC proof carries an incremental commitment to advice across computation steps. Its interface includes generator $G$, encoder/key generator $K$, prover $P$, verifier $V$, and an incremental commitment scheme $IC=(Gen,Commit,Open)$. At step $i$, the prover updates both the computation state, $z_{i+1}=F(z_i,\omega_i)$, and the commitment, $C_{i+1}=IC.Commit(pp_{IC},C_i,\omega_i)$. [Nebula PDF, pp. 4–6] |
| **Read-write memory mechanism** | **Author-stated:** Nebula maintains initial, read, and write multisets, $IS$, $RS$, and $WS$. Each memory operation uses address-value-timestamp tuples; timestamps and consistency assertions enforce that a returned value is older than the current operation. A randomized public-coin multiset hash checks the relevant multiset equality. For $e_i=(a_i,v_i,t_i)$, the fingerprint is $\prod_i(a_i+\gamma_1v_i+t_i\gamma_1^2-\gamma_2)$. [Nebula PDF, pp. 3, 7–9] |
| **Universal switchboard circuit** | **Author-stated:** Given $\ell$ R1CS circuits, Nebula stitches them into one circuit with selector variables. The construction uses one-hot selection, binary selector constraints, and input-consistency constraints. It adds $\ell(\lvert x\rvert+1)+1$ constraints, does not increase degree, and has $O(n)$ active variables according to the paper’s complexity table. [Nebula PDF, pp. 10–12] |
| **Three-layer architecture** | **Author-stated:** Layer 1 uses CC-IVC to execute the step function and carry memory-operation advice; Layer 2 finalizes the proof by computing multiset hashes under the final commitment; Layer 3 folds the resulting IVC proofs to restore incrementality beyond the finalization point. [Nebula PDF, pp. 7–9] |
| **Security model** | **Author-stated:** The definitions use PPT algorithms and, where extraction or simulation is required, expected-polynomial-time extractors or simulators. The formal framework includes incremental commitments, CC-IVC, commitment schemes, hiding, homomorphism, succinctness, arguments of knowledge, non-interactivity, zero-knowledge, IVC, and folding schemes. [Nebula PDF, pp. 4–6, 15–18] |
| **Cryptographic assumptions** | **Author-stated:** The paper works over a finite field $\mathbb{F}$, uses a security parameter $\lambda$ and negligible functions, and assumes suitable commitment and multiset-hash mechanisms. The multiset hash can be instantiated using either a deterministic elliptic-curve/cryptographic-hash construction or a randomized public-coin Reed–Solomon-fingerprint construction. [Nebula PDF, pp. 3, 15–18] |
| **Core security condition for memory checking** | **Author-stated:** The memory-checking corollary assumes a prime-order field, timestamps in the field, and fewer memory operations than the field characteristic, $N<\lvert\mathbb{F}\rvert$. Under the stated condition that every read returns the last tuple written to that location, the paper gives a multiset-equality result over the public-coin challenges. [Nebula PDF, p. 7] |
| **Main formal results** | **Author-stated:** The paper states that its CC-IVC construction follows from folding schemes; gives the overhead of CC-IVC over IVC; proves the multiset-hash memory-checking corollary; establishes Nebula as an IVC scheme with sequential-consistency semantics; proves the switchboard parsing lemma; and derives a non-uniform IVC construction from the switchboard and Nova’s uniform IVC. [Nebula PDF, pp. 6–11] |
| **Prover space complexity** | **Author-stated:** The paper reports prover space of $O(\vert F\rvert+\lvert M\rvert)$, where $\lvert M\rvert$ is global-memory size. [Nebula PDF, p. 9] |
| **Per-operation and folding costs** | **Author-stated:** The complexity table reports, for Nebula, six small committed elements, six arbitrary committed elements, six constraints per operation, and $4\rvert H\lvert + 4\lvert G\rvert$ constraints per folding step. Nebula-Opt removes the six arbitrary elements but adds an $O(\log \lvert M\rvert)$ folding-step term. [Nebula PDF, p. 10] |
| **Proof and verifier succinctness** | **Author-stated:** The IVC proof size is independent of the iteration count, and the general succinctness definition bounds communication and verifier time polylogarithmically in the structure and witness sizes. [Nebula PDF, pp. 4, 16–17] |
| **Reported prototype results** | **Author-stated:** The supplied bibliographic record reports a 30× smaller constraint system for the EVM than standard memory-checking methods and more than 260× faster proof generation for a standard ERC-20 transfer than the baseline Nova implementation. The paper’s benchmark discussion also reports that baseline Nova ran out of memory beyond one batched EVM step per Nova step, whereas Nebula could batch up to 20 EVM steps per Nova step. [Nebula bibliographic record; Nebula PDF, p. 13] |
| **Author-stated limitations and caveats** | The construction assumes $N<\lvert\mathbb{F}\rvert$ for the memory-checking result; CC-IVC alone does not restore incrementality because memory-checking challenges must be sampled after the relevant witnesses are committed; each memory operation commits to two address-value-timestamp tuples; EVM values represented by two field elements increase hash costs; persistent-storage scan cost depends on the number of initialized keys; experiments use a cheaper custom hash rather than SHA3; and common opcode functionality is duplicated across subcircuits even though the switchboard charges only for active parts. [Nebula PDF, pp. 1–2, 9, 12–13] |
| **Implementation and modeling caveats** | **Author-stated:** For exposition, the switchboard circuits are assumed to share public input and output lengths, although their matrix dimensions may differ. The EVM prototype’s custom hash improves proving efficiency and is used for relative baseline comparisons rather than as a direct SHA3 cost estimate. [Nebula PDF, pp. 11, 13] |
| **Open/future direction explicitly indicated** | **Author-stated:** The authors expect similar performance improvements when Nebula’s techniques are implemented over other folding schemes. [Nebula PDF, p. 13] |
| **Research interpretation: technical questions** | 1. How should the field size be selected when the maximum number of memory operations is not known in advance? 2. Can memory checking remain incrementally updateable without the layered finalization and refolding arrangement? 3. What concrete security loss results from the public-coin fingerprint and finite-field parameter choices? 4. Can the switchboard share common opcode logic without reintroducing selector or multiplexer overhead? |
| **Research interpretation: experimental questions** | 1. Reproduce the EVM results with a standard cryptographic hash such as SHA3 rather than the cheaper experimental hash. 2. Report wall-clock proving time, peak memory, proof size, and verification time across transaction classes and batch sizes. 3. Benchmark Nebula over multiple folding schemes and hardware environments. 4. Quantify the persistent-storage scan cost for contracts with millions of initialized keys. |
| **Research interpretation: broader directions** | 1. Develop adaptive field and memory parameters for workloads with dynamic operation counts. 2. Study maliciously adaptive memory providers and adversarially scheduled reads and writes. 3. Extend the construction to heterogeneous input/output lengths without relying on the exposition-only equal-length assumption. 4. Derive concrete end-to-end security bounds that combine commitment security, fingerprint soundness, folding security, and Fiat–Shamir or public-coin assumptions where applicable. |
