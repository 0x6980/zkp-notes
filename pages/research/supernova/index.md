# SuperNova: Research Summary Table

**Paper:** [SuperNova: Proving Universal Machine Executions without Universal Circuits](https://eprint.iacr.org/2022/1758). 
**Authors:** Abhiram Kothapalli and Srinath Setty  

**Interpretation note:** Rows marked **Author-stated** summarize definitions, constructions, claims, assumptions, or limitations stated in the SuperNova paper. Rows marked **Research interpretation** are analytical synthesis or proposed research directions and are not presented as direct claims by the authors.

| Item | Summary |
|---|---|
| **Research problem** | **Author-stated:** Prove correct execution of programs on stateful machines with a specified instruction set, such as EVM, RISC-V, or Wasm, while keeping proofs succinct, verification efficient, and per-step proving cost proportional only to the invoked instruction circuit. Prior universal-circuit approaches charge at least for the sum of all supported instruction circuits on every step. [SuperNova PDF, pp. 0–2] |
| **Motivation and application** | **Author-stated:** Succinct execution proofs can enable replicated systems without replicated execution, including rollups, by allowing an untrusted cloud prover to execute a virtual machine and produce a proof that a replicated system verifies instead of re-executing the batch. [SuperNova PDF, pp. 1–2] |
| **Main contribution** | **Author-stated:** SuperNova realizes non-uniform incremental verifiable computation (NIVC) using folding schemes. It supports an arbitrary collection of instruction functions and a control function, maintains one running instance per instruction, and folds each step into the running instance selected by the control function. [SuperNova PDF, pp. 0–5, 11–17] |
| **Relation to Nova** | **Author-stated:** SuperNova generalizes Nova from a single instruction to an arbitrary instruction set. The paper states that the prover costs and recursion overhead are similar to Nova’s and that SuperNova is equivalent to Nova when the machine supports one instruction. [SuperNova PDF, p. 3] |
| **Computational model** | **Author-stated:** The model contains polynomial-time, non-deterministic functions $(F_1,\ldots,F_\ell)$ and a control function $\varphi$. Each $F_j$ maps a state and non-deterministic advice to a next state, while $\varphi$ selects the instruction index from the current state and advice. The functions are represented using R1CS. [SuperNova PDF, pp. 4, 11–12] |
| **NIVC interface** | **Author-stated:** Public-parameter generation $G$ outputs $pp$; deterministic encoding $K(pp,(\varphi,(F_1,\ldots,F_\ell)))$ outputs prover and verifier keys; the prover $P$ extends an accepted proof using the current state and advice; and verifier $V$ checks the claimed state and NIVC proof. [SuperNova PDF, pp. 11–12] |
| **Committed relaxed R1CS** | **Author-stated:** An instance is $(\bar E,u,\bar W,x)$ with commitments to the error vector and witness, scaling factor $u$, and public input/output $x$. A witness satisfies the committed relation when the commitments open correctly and $(A Z)\circ(B Z)=u(C Z)+E$ for $Z=(W,x,u)$. [SuperNova PDF, pp. 7, 10] |
| **Folding mechanism** | **Author-stated:** A non-interactive folding scheme combines two same-structure relaxed-R1CS instances into one instance whose satisfiability implies satisfiability of the inputs under knowledge soundness. SuperNova uses this primitive to update a constant-size running instance for each instruction circuit. [SuperNova PDF, pp. 5, 7–10, 13–14] |
| **Why multiple running instances are needed** | **Author-stated:** A standard relaxed-R1CS folding scheme requires both inputs to have the same structure. Since different instruction circuits have different structures, SuperNova maintains a list $U_i$ where $U_i[j]$ accumulates prior executions of the augmented circuit associated with instruction $j$. [SuperNova PDF, pp. 13–14] |
| **Selector and program-counter mechanism** | **Author-stated:** The control function $\varphi$ computes the next program counter. The augmented circuit uses the previous program counter $pc_i$ to select the running instance $U_i[pc_i]$ into which the current step instance is folded, checks that $1\le pc_i\le\ell$, and hash-links the statement to the verifier key, counter, program counter, initial state, current state, and running-instance list. [SuperNova PDF, pp. 14, 16–17] |
| **Augmented circuit $F'_j$** | **Author-stated:** $F'_j$ executes $F_j$, computes the next program counter using $\varphi$, handles the base case, verifies the current step’s public input, checks freshness of the step instance, folds the current instance into the selected running instance using NIFS verification, and outputs a hash-linked next statement. [SuperNova PDF, pp. 13–16] |
| **Prover algorithm** | **Author-stated:** The prover parses the current proof, initializes the list of running instances in the base case, otherwise folds the current step witness into the selected running-instance witness, computes the next program counter, traces the next augmented circuit, and outputs the updated running instances, current-step instance/witness, and program counter. [SuperNova PDF, p. 17] |
| **Verifier algorithm** | **Author-stated:** For nonzero steps, the verifier checks the hash-linked public input, program-counter range, freshness of the current instance, satisfaction of every running instance with its witness, and satisfaction of the current-step witness under the selected augmented-circuit structure. [SuperNova PDF, p. 17] |
| **Security properties** | **Author-stated:** The construction is stated to have perfect completeness and knowledge soundness. The security model permits an adaptive adversary to choose the control function, instruction functions, and statement after seeing public parameters/CRS, subject to the formal experiment. [SuperNova PDF, pp. 6, 11–12, 17–19] |
| **Cryptographic assumptions** | **Author-stated:** The framework uses a finite field of size $2^{\Theta(\lambda)}$, additively homomorphic succinct vector commitments, and a common-reference-string preprocessing model. The folding scheme is analyzed in the random-oracle model; Fiat–Shamir heuristically instantiates the random oracle with a concrete hash function in the plain model. Pedersen commitments are given as an example of the commitment layer. [SuperNova PDF, pp. 6–10] |
| **Per-step prover cost** | **Author-stated:** The prover’s space and time at step $i$ are linear in the size of the function applied at that step, $O_\lambda(\lvert F_{\varphi(z_{i-1},\omega_{i-1})}\rvert)$. The paper also states that the cost is dominated by two multiexponentiations proportional to the executed instruction circuit. [SuperNova PDF, pp. 3, 12] |
| **Committed-folding costs** | **Author-stated:** For $n$-sized committed relaxed-R1CS instances, the folding prover takes $O_\lambda(n)$ time, while verifier time and communication are $O_\lambda(1)$ under the paper’s asymptotic notation. [SuperNova PDF, p. 10] |
| **Augmented-circuit size** | **Author-stated:** With Pedersen commitments, $|F'_j|=|\varphi|+|F_j|+o(2G+2H+R)$, where $G$ is the cost of group scalar multiplication, $H$ the cost of hashing, and $R$ the cost of encoding the random-oracle challenge. [SuperNova PDF, p. 22] |
| **Instruction-count overhead** | **Author-stated:** A natural verifier circuit scales linearly with the number of instructions $\ell$. Hashing initially also scales with $\ell$, but Merkle proofs can reduce it to $O_\lambda(\log\ell)$ constraints and multiset-based offline memory checking can reduce it to $O_\lambda(1)$. [SuperNova PDF, pp. 5, 22] |
| **Raw proof size** | **Author-stated:** After $N$ steps, the prover holds $\ell$ running instances and one last-step R1CS instance. The proof size is independent of $N$ but proportional to the sum of the instruction-circuit sizes and is therefore not concretely small for a rich instruction set. [SuperNova PDF, pp. 5–6] |
| **Succinctness and zero-knowledge** | **Author-stated:** The raw NIVC proof is not zero-knowledge and is not concretely succinct. The paper proposes invoking a general-purpose zkSNARK, such as Spartan, to obtain a compressed zero-knowledge proof of knowledge of a valid NIVC proof; formal details are deferred to near-term work. [SuperNova PDF, pp. 5–6, 13] |
| **Base-case and state-compression details** | **Author-stated:** The paper identifies a running-instance growth issue if full $U_{i+1}$ is exposed as public input/output. It alleviates this by outputting a hash of the outputs and using a preimage as non-deterministic input in the next step. The exposition also initially omits the definition of $\Pi_0$ and requires additional folding-prover advice as non-deterministic input. [SuperNova PDF, p. 15] |
| **Comparison with prior approaches** | **Author-stated:** Universal circuits charge for all supported instructions; Buffet uses line-by-line non-uniform compilation but needs static execution bounds and does not directly provide the same incremental stateful-machine treatment; vRAM and MIRAGE can achieve invoked-instruction cost profiles but are not incremental in the same way and may reveal instruction-invocation counts or require global trace invariants. [SuperNova PDF, pp. 2–3] |
| **Implementation evidence** | **Author-stated:** The SuperNova paper is theoretical and does not report a complete implementation benchmark with concrete proving time, memory, proof-size, or verification measurements. Therefore, the a-la-carte advantage is formally motivated but not quantitatively validated for a specific deployed machine in this source. [SuperNova PDF, pp. 0–22] |
| **Author-stated limitations** | SuperNova does not immediately support parallel proof generation; the raw proof is not concretely succinct or zero-knowledge; a zkSNARK wrapper is needed and its formal details are deferred; selector/hash overhead can depend on $\ell$ before optimization; and the exposition assumes equal input/output and circuit sizes. [SuperNova PDF, pp. 3, 5–6, 13, 16, 22] |
| **Explicit future work** | **Author-stated:** Provide a SuperNova-specific solution for parallel proving and supply the formal details of the zkSNARK of valid NIVC proofs. [SuperNova PDF, pp. 3, 13] |
| **Research interpretation: security questions** | 1. What end-to-end security theorem results from composing NIVC, folding, commitments, Fiat–Shamir, and the zkSNARK wrapper? 2. What concrete soundness loss follows from replacing the random oracle with a concrete hash? 3. How are adaptive instruction selection and hash-linked running state handled under the strongest practical adversarial model? 4. What metadata and instruction-sequence information remain visible after compression? |
| **Research interpretation: experimental questions** | 1. What are the wall-clock proving time and peak memory for EVM, RISC-V, and Wasm workloads? 2. How does cost vary with instruction-circuit size, instruction-set cardinality, and skew in opcode frequency? 3. What are the concrete costs of Merkle or multiset-based selector optimizations? 4. How much overhead does the zkSNARK wrapper add to raw NIVC proving and verification? |
| **Research interpretation: broader directions** | 1. Generalize to heterogeneous instruction interfaces without padding-driven cost inflation. 2. Co-design circuit grouping, selector representation, and memory-checking strategy. 3. Develop parallel proving that preserves the a-la-carte profile. 4. Establish concrete parameter tables combining field size, commitment security, hash security, recursion depth, and instruction-set size. |
